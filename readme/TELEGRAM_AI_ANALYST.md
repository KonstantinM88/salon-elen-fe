# Telegram AI-аналитик и Search Console

## Назначение

Закрытый Telegram AI-аналитик доступен только chat ID из
`TELEGRAM_ADMIN_CHAT_ID`. Он работает в режиме read-only и не меняет записи,
клиентов, услуги, цены, расписание или настройки сайта.

Команды администратора:

- `/ask` - открыть кнопочное меню AI-аналитика;
- `/report` - получить дневной отчёт за вчера;
- `/admin` - открыть общее администраторское меню;
- `/next7`, `/next14`, `/next30` - показать ближайшие записи.

Меню `/ask` содержит поиск, трафик, бронирования, отзывы, локальную видимость,
локальных конкурентов, общую сводку и произвольный вопрос через Telegram
ForceReply. Произвольный
вопрос не создаёт состояние в БД: webhook распознаёт ответ по исходному
ForceReply-сообщению.

## Search Console

Серверный модуль `src/lib/google/search-console.ts` использует Google service
account и Search Console Search Analytics API. Он не запускает URL Inspection,
не проверяет отдельные URL и не обращается к PostgreSQL.

Production-переменные:

```env
GSC_CLIENT_EMAIL="service-account@project.iam.gserviceaccount.com"
GSC_PRIVATE_KEY_BASE64="base64-encoded-private-key"
GSC_SITE_URL="https://permanent-halle.de/"
```

Вместо `GSC_PRIVATE_KEY_BASE64` поддерживается `GSC_PRIVATE_KEY` с переводами
строк `\n`. Base64 предпочтительнее для PM2/Hostinger. Значение
`GSC_SITE_URL` должно точно совпадать со свойством Search Console. Для URL-prefix
это `https://permanent-halle.de/`; для domain property API использует формат
`sc-domain:permanent-halle.de`.

Service account необходимо добавить пользователем с правом чтения в нужное
свойство Search Console и включить Google Search Console API в Google Cloud.
Секретный ключ нельзя коммитить или выводить в логи.

Запрос Search Analytics:

- использует семь дней, заканчивающихся за два дня до текущей salon-local даты;
- получает не более 250 строк с dimension `query`;
- отдельно получает агрегат сайта за тот же период;
- имеет общий timeout 20 секунд;
- возвращает typed fallback при отсутствии конфигурации или ошибке.

TOP-10 сортируется по показам, затем по кликам и лучшей средней позиции. Блок
анализа популярных запросов отдельно показывает до пяти лидеров видимости,
быстрые возможности на средних позициях 4-20 и запросы с CTR ниже 3% при
минимуме пяти показов. Показы GSC означают показы именно
`permanent-halle.de` в результатах Google, а не общий search volume по
Германии. Position является средней позицией за период. Данные обычно
поступают примерно с двухдневной задержкой.

## AI-рекомендации

Модель из `OPENAI_MODEL` получает не более 15 агрегированных строк GSC:

- точный query;
- impressions;
- clicks;
- CTR;
- average position.

В AI также передаётся только проверенный публичный конкурентный контекст из
`src/lib/analytics/local-competitors.ts`: название, адрес, сайт и опубликованные
направления услуг. Модель не получает и не должна выводить рейтинги, трафик,
качество, долю рынка, точные расстояния или отсутствующие услуги конкурентов.

Модель возвращает до пяти классификаций `query || action`. Сервер принимает
только точный запрос из GSC, разрешённые действия `snippet`, `content`,
`internal_links`, `local_proof`, `differentiate`, `monitor` и только одно
действие на запрос. Числа и финальный русский текст формирует сервер из реальных
метрик и подтверждённых фактов Salon Elen.

При отсутствии ключа, timeout 15 секунд, ошибке OpenAI или невалидном ответе
используется deterministic fallback. Поэтому OpenAI не может заблокировать
ежедневный отчёт. В модель не передаются IP, имена, телефоны, email, сообщения
клиентов, идентификаторы, токены, бронирования или секреты.

## Локальные конкуренты

Отчёт показывает пять локальных салонов с пересекающимися публичными услугами:

- Penewlope by Iwa Penewa;
- Miss BeauTyna;
- Glow Beautybar by Ilona;
- Glitzerstübchen Halle;
- PMU Studio Halle/Saale.

Список является рабочим ориентиром по Halle (Saale), а не рейтингом Google Maps
и не утверждением о пяти математически ближайших точках. Источники и дата
проверки хранятся централизованно в
`src/lib/analytics/local-competitors.ts`. Обновляйте их только после проверки
официальных сайтов. Отчёт не выполняет ежедневный веб-поиск конкурентов.

## Источники кнопочного аналитика

- Поисковые запросы и локальная видимость: Search Console, без БД.
- Конкуренты: проверенный публичный справочник плюс GSC-приоритеты AI, без БД.
- Трафик и бронирования: агрегированные данные приложения за вчера.
- Общая сводка: максимум два источника - приложение, затем Search Console.
- Отзывы: честный статус «источник не подключён», пока нет read-only Google
  Business Profile интеграции.

Новые DB-запросы отчётов выполняются последовательно. Новых cron, polling,
background worker, keep-alive запросов, Prisma Client или таблиц нет.

## Telegram 4096

`src/lib/telegram/sender.ts` автоматически делит длинный текст сначала по
переводу строки, а при невозможности - по безопасному лимиту 4000 символов.
Части отправляются последовательно. При ошибке отправка останавливается;
получатель считается успешным только после всех частей. `reply_markup` и inline
keyboard прикрепляются только к последней части, а preview ссылок остаётся
выключенным.

## Production-проверка

После деплоя без отправки тестов клиентам:

1. Проверить `pm2 logs salon-elen-fe` на отсутствие секретов и ошибок загрузки.
2. Выполнить `/start` и убедиться, что в меню появились `/report` и `/ask`.
3. Выполнить `/report`: проверить период, totals, TOP-10, популярные запросы,
   пять конкурентов и пять рекомендаций.
4. Выполнить `/ask` и открыть каждый раздел, включая «Конкуренты и AI».
5. Задать один безопасный агрегированный вопрос через ForceReply.
6. Проверить сообщение длиннее 4096 символов и клавиатуру только в последней части.
7. При временном отключении OpenAI убедиться, что отчёт приходит с fallback.
8. При неверной GSC-конфигурации убедиться, что основной отчёт всё равно приходит.

Новый cron не требуется. Используется существующий ежедневный вызов:

```cron
0 8 * * * /usr/bin/curl -sS -X POST "https://permanent-halle.de/api/admin/ai-health?action=daily" -H "Authorization: Bearer $CRON_SECRET" >/dev/null 2>&1
```
