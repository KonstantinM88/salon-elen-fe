## Deployment screenshots

1. CSS optimization warnings are not by themselves a failed build. The deploy
   script places an old build in `.next.previous-*` before building; previously
   root-wide Tailwind scanning could read those unignored artifacts. Tailwind
   now scans only live `src` content, excluding generated code and legacy
   backups. `npm run test:styles` validates this boundary and real safe-area CSS.
   The exact corrupt source file on the production host was not available for
   inspection; the change removes that unintended input category.
2. The npm vulnerability summary is a dependency audit, not a Next compile error.
3. `Server Reference ID did not match the expected format` with values such as
   `y` or a short hex string indicates invalid action IDs. It may be automated
   probing or incompatible clients. It differs from a valid old action ID
   missing after deployment. The screenshots alone do not identify the sender
   or prove compromise. Correlate timestamps with nginx requests, then reproduce
   a real form in a fresh tab. Do not disable auth/action validation or hide logs.

The admin deployment watcher also removes Effect Events from its effect
dependencies. React intentionally changes their identity on render; depending
on them could restart the probe/timer on every status render instead of retaining
the intended one-minute cadence and focus/visibility checks.

The in-place PM2 script intentionally stops the app before changing dependencies
or build output. Its build backup does not restore old node_modules; a full
dependency rollback requires the matching previous commit/lockfile and rebuild.
See [PM2 runbook](PM2_DEPLOY_RUNBOOK.md).
